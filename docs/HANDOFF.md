# 작업 인수인계

이 문서는 Claude Code와 Codex가 세션이 바뀌어도 현재 프로젝트 상태를 빠르게 파악할 수 있도록 유지한다.

작업이 진행될 때마다 최신 상태로 업데이트한다.

## 프로젝트 기본 정보

- 장르: 2D 플랫폼 액션
- 플랫폼: 웹 브라우저
- 필수 언어: 한국어
- 그래픽 스타일: 귀엽고 아기자기한 픽셀아트
- 핵심 플레이: 이동과 점프를 이용해 장애물을 피하고 스테이지를 클리어
- 주요 디자인 담당: Claude Code
- 주요 구현 및 에셋 지원 담당: Codex

## 핵심 요구사항

- 브라우저에서 별도 설치 없이 실행 가능해야 한다.
- 한국어를 완전히 지원해야 한다.
- 픽셀아트 스타일을 일관되게 유지한다.
- 실제 브라우저 화면을 확인하면서 디자인을 반복 개선한다.
- 조작감과 플레이 가독성을 최우선으로 한다.
- 지나치게 복잡한 기능은 초기에 추가하지 않는다.

## Codex 요청 사항

### 프로토타입을 디자인 기준으로 전환 (Claude 요청, 2026-09-26 / Codex 구현 완료)

지금의 외부 의존성 없는 Canvas 2D 구조는 좋다. 그대로 유지하고 아래만 바꿔 달라. 기준은 `docs/DESIGN.md` 1장과 5장이다.

1. **내부 해상도 320×180 → 480×270**
   - 스테이지 좌표를 16px 격자에 맞춘다. 기본 지면 윗면은 y=224 (타일 14행)
   - 플레이어 그림 16×16, 충돌 박스는 약 10×14
2. **화면 배율과 페이지 구성**
   - 캔버스가 창 전체를 채우고, 남는 영역은 `#2f2a3a` 레터박스로 둔다. 현재의 3배 상한은 없앤다
   - 배율 규칙: 창에 맞는 배율이 2 이상이면 정수, 2 미만이면 비정수 (둘 다 nearest). 참고 구현은 `mockup/mockup.js`의 `fit()`
   - 캔버스 밖의 HTML 제목·안내·상태 문구(`#stage-title`, `#instructions`, `#status`)는 없앤다. 이 정보는 캔버스 안 HUD와 알림으로 옮기며, 그림은 Claude가 맡는다. 스크린리더용 `aria-live` 상태 문구는 화면 밖에 숨겨서 유지해도 좋다
3. **텍스트 관리**
   - `src/locale/ko.js` 대신 `locales/ko.json` (키 기반, 목업이 이미 사용 중)으로 합친다. 기존 문구는 키를 붙여 옮긴다. `t(key)` 형태의 조회 함수 하나
   - 폰트 `assets/fonts/galmuri/`: Galmuri11 12px / Bold 12px / Galmuri9 10px만 쓴다 (다른 크기는 흐려지는 것을 측정으로 확인함). `document.fonts.load` 후 그리기 시작
   - 캔버스 텍스트는 `mockup/mockup.js`의 `textSprite` 방식(오프스크린에 그린 뒤 알파 이진화, 위쪽 2px 여백)을 쓴다. 여백이 없으면 한글 첫 행이 잘린다
4. **체크포인트**
   - 스테이지 데이터에 `checkpoints` 배열 (가로등). 닿으면 활성화되고, 장애물에 닿거나 떨어지면 **마지막 활성 체크포인트에서 즉시** 다시 시작
   - R은 스테이지를 처음부터 다시 시작
   - 렌더러가 쓸 수 있게 각 체크포인트의 활성 여부를 상태로 노출
5. **픽셀 정확도**: 가시 등 모든 도형은 정수 좌표 `fillRect`로 그린다. 지금 가시는 path 채우기라 가장자리가 흐리다. 카메라 x도 정수로 반올림
6. **조작감 수치**(속도, 가속, 점프 높이, 중력, 코요테 타임, 점프 입력 버퍼)를 한 객체에 모아 조정하기 쉽게 해 둔다
7. 완료 후 테스트를 갱신하고, 바뀐 실행 방법과 구조를 이 문서에 기록한다

이 작업이 끝나면 Claude가 `src/render.js`의 비주얼을 목업 기준으로 교체한다. 그 전에 `render.js`의 그림을 크게 다듬을 필요는 없다.

### 방향 전환 때 화면 흔들림 줄이기 (사용자 요청, Claude 정리, 2026-09-26) ✅ 코드 및 시뮬레이션 검증

**사용자 피드백**: "방향 전환할 때 화면이 너무 많이 흔들려서 머리가 아프네요." 나머지 화면은 모두 마음에 든다고 했다.

**원인**: `src/render.js`의 `updateCamera()`. 카메라 목표가 `p.x + 5 - W / 2 + p.face * 40`이라, 방향을 바꾸는 순간 목표가 반대쪽으로 **80px 한 번에** 옮겨 가고, 카메라가 매 프레임 12%씩(약 0.3초) 따라간다. 좌우를 짧게 번갈아 누르면 화면이 크게 왔다 갔다 한다.

**요청** (이 부분은 Codex가 `src/render.js`의 `updateCamera()`를 직접 고쳐도 된다. 다른 그림 코드는 건드리지 않는다)
1. 앞을 더 보여 주는 거리를 40px → **24px**로 줄인다
2. 앞보기 거리(`look`)를 카메라 추적과 **따로** 천천히 바꾼다: 초당 최대 30px(프레임당 약 0.5px)로 `face * 24`에 다가간다
3. 새 방향으로 **0.3초 이상 계속 움직였을 때만** 앞보기 방향을 바꾼다. 제자리에서 돌아서기, 짧게 톡 누르기, 2단 점프 회전 연출은 무시한다
4. 카메라 추적에 **가운데 ±16px 여유 구간**을 둔다: 고양이가 그 안에서 움직이면 카메라는 멈춰 있는다. 따라갈 때는 12% 대신 8%
5. 부활·스테이지 시작 때 바로 맞추는 동작(`fx.cam = null`)은 그대로 둔다

**확인 기준**
- 좌우를 0.2초마다 번갈아 누르는 동안 카메라 이동이 8px 이하
- 한 방향으로 달리다 반대로 돌아 계속 달리면, 앞보기 전환이 1.5초 이상에 걸쳐 부드럽게 이뤄진다
- 헤드리스 브라우저에서 위 두 경우의 카메라 x를 기록해 HANDOFF에 적어 달라. 사용자가 실제로 다시 확인할 예정이다

## 현재 알려진 문제

- 모바일 터치 조작은 헤드리스 브라우저 터치 에뮬레이션으로만 확인했다. 실제 휴대폰에서의 조작감은 아직 확인하지 못했다.

- 원격 저장소: GitHub `origin`, 브랜치 `main` (공개 전환 예정). 개인·도구 설정(`.claude/`, `.gstack/`, `.vercel/`)은 `.gitignore`로 뺐다. 문서·커밋에 계정·팀 이름, 이메일을 쓰지 않는다. 커밋 작성자는 GitHub 숨김 이메일을 쓴다 (실제 이메일 커밋은 push가 막힘).
- 개발 서버 `npm run dev`는 이 컴퓨터에서만 열린다(127.0.0.1). 휴대폰 확인용 `npm run dev:lan`은 프로젝트 폴더 전체를 같은 네트워크에 보여 주므로 잠깐만 쓴다.
