# 디자인 가이드

`docs/GAME_VISION.md`를 따르는 시각·UI 기준 문서. Claude Code가 관리한다.
값을 바꾸면 `mockup/mockup.js`의 팔레트와 치수도 함께 바꾼다.

확정 사항 (2026-09-26, 사용자 결정)

- 테마: **동네 골목**
- 실패 처리: **체크포인트 즉시 재시작** (게임 오버 화면 없음, 목숨·하트 없음)
- 내부 해상도: **480×270**
- 고양이 16×16 유지, HUD는 **A 외곽선 글자** (사용자 확정, 2026-09-26)

게임 이름: **Peaceful Streets** (사용자 확정, 2026-09-26)

## 1. 화면과 렌더링

| 항목 | 값 |
|---|---|
| 내부 해상도 | 480×270 (16:9) |
| 타일 | 16×16px (화면당 가로 30칸, 세로 약 17칸) |
| 플레이어 | 16×16 (충돌 박스는 이보다 작게, 약 10×14) |
| 기본 지면 | 윗면 y=224 (타일 14행). 지형·발판·장애물 좌표는 16px 격자에 맞춘다 |
| 확대 | 창에 맞는 배율이 2 이상이면 **정수 배율**. 2 미만이면 비정수 배율로 창을 채운다 (둘 다 nearest, 스무딩 없음) |
| 레터박스 색 | `#2f2a3a` |

## 2. 레이어와 대비 규칙

뒤에서 앞으로. **앞 레이어일수록 대비와 채도가 높다.**

| 레이어 | 내용 | 규칙 |
|---|---|---|
| 하늘 | 3단 색 띠 + 구름 | 가장 밝음, 외곽선 없음 |
| 먼 배경 | 산 능선 두 겹, 아파트(창문 격자), 뾰족 지붕·물탱크 집, 송신탑 | 채도·대비 낮음, 외곽선 없음, 패럴랙스 약 0.2 |
| 중간 배경 | 빌라(평지붕·물탱크·실외기), 기와집, 차양 가게, 파란 지붕 집(굴뚝), 빨랫줄, 담장, 문 앞 화분, 나무, 전봇대·변압기·전선. 480px마다 반복 | 파스텔, 외곽선 없음 (지붕 윗선만 허용), 패럴랙스 약 0.5 |
| 플레이 레이어 | 지형, 발판, 장애물, 수집품, 체크포인트, 깃발 | **진한 외곽선 1px** 필수 |
| 플레이어 | 고양이 | 진한 외곽선 1px, 가장 눈에 띄는 색 |
| HUD / UI | 텍스트, 패널 | 아래 5장 참조 |

- **빨강·주황 계열(`hazard`, `pot`)은 위험한 것에만 쓴다.** 체크포인트, 수집품, UI 강조에는 쓰지 않는다. (그래서 체크포인트는 빨간 우체통이 아니라 노란 불빛 가로등으로 정했다)
- 배경 오브젝트에는 외곽선을 쓰지 않는다. 외곽선 여부만으로 "닿을 수 있는 것"과 "배경"이 구분되게 한다.

## 5. 글꼴과 텍스트

- **Galmuri11 12px** (본문, 메뉴, HUD), **Galmuri11 Bold 12px** (제목), **Galmuri9 10px** (작은 안내).
- 이 크기에서만 안티앨리어싱 없이 픽셀이 정확히 맞는다 (브라우저에서 측정: 12px / 10px에서 반투명 픽셀 0개. 다른 크기는 흐려진다). **다른 크기를 쓰지 말고, 크게 보여야 하면 정수배(×2, ×3)로 확대한다.**
- 폰트 파일: `assets/fonts/galmuri/` (SIL OFL 1.1, `OFL.md`). 현재 전체 글리프가 들어 있어 파일당 약 0.2~0.5MB. 배포 전에 사용하는 한글만 남기는 서브셋 작업이 필요하다.
- 캔버스에 텍스트를 그릴 때 **위쪽에 2px 여백**이 필요하다. Galmuri 글리프 윗줄이 `textBaseline='top'` 기준선보다 위에서 시작해, 여백이 없으면 첫 행이 잘린다 (ㄷ→ㄴ, ㅁ→ㅂ로 보이는 문제를 실제로 확인함).
- 게임 화면 위 글자: `cream` 글자 + `outline` 1px 외곽선. 패널 위 글자: `outline` 색, 외곽선 없음.
- 모든 문구는 `locales/ko.json`의 키로 관리한다. 코드에 한글 문자열을 직접 쓰지 않는다.
- 타이틀 로고: "Peaceful Streets" Bold ×3. 단어마다 색을 바꾸고(크림 → 꽃 분홍), 3px 아래 진한 그림자, 양 끝에 2배 꽃(1px 흔들림). 영어 로고라 한글 받침이 뭉개지던 문제는 없다. 전용 로고 픽셀아트는 에셋 단계에서 다시 검토한다.

## 6. HUD

화면 위쪽 한 줄만 쓴다. 배경 패널 없이 외곽선 글자로 가볍게.

```
[8,6] 1-1  골목 입구                      ✿ × 12   ◷ 0:42 [472,6]
```

- 왼쪽: 스테이지 번호 + 이름. 스테이지 시작 시 가운데 배너로 약 2.5초 크게 보인 뒤 이 자리로 줄어든다.
- 오른쪽: 꽃 **모은 개수 / 스테이지 전체** (예: `5 / 17`), 경과 시간. 아이콘 9×9. 전체 개수를 보여 줘 다 모으고 싶게 한다
  - 꽃을 먹으면 숫자와 아이콘이 0.25초 동안 3px 튀어 오른다
  - 전부 모으면 숫자가 노란색(`focus`)으로 바뀌고 아이콘 둘레가 반짝인다
  - 클리어 화면: 전부 모았으면 꽃 줄 아래에 노란 배지 "꽃을 전부 모았어요!"(`clear.allFlowers`), 패널이 한 줄만큼 늘어난다
- 가장자리 여백 8px. 플레이 영역에는 HUD를 두지 않는다.
- 카메라: 앞보기 거리 24px, 방향 전환은 천천히(초당 30px, 0.3초 이상 새 방향으로 움직일 때만). 화면이 크게 흔들리면 멀미가 난다는 사용자 피드백이 있었다 (HANDOFF의 Codex 요청 참고)
- "체크포인트!" 같은 일시적 알림은 해당 오브젝트 위에 Galmuri9로 띄웠다가 사라지게 한다.

## 7. 메뉴와 패널

- 패널: `cream` 바탕, `outline` 1px, 모서리 1px 깎기, 아래쪽 안쪽에 `panelShade` 1px. 9-slice로 구현한다.
- 선택 항목: `focus` 배경 막대 (글자 폭 + 좌우 6px, 높이 16px) + 왼쪽에 ▶ 커서. 선택 시 커서가 1px 튀는 움직임을 준다.
- 항목 간격: 메뉴 18px, 일시정지·클리어 22px.
- 뒤 화면 어둡게: `rgba(47,42,58,0.55)`.
- 키보드 우선: ↑↓ 이동, Space/Enter 선택, Esc 뒤로.

화면 흐름

```
타이틀 ─→ [시작 배너] 플레이 ─→ 클리어 ─→ 다음 스테이지
  │                │ Esc
  │                └→ 일시정지 (계속하기 / 다시 시작 / 설정 / 타이틀로)
  └→ 설정 (배경음 / 효과음 / 화면 배율 / 조작 안내)
```

| 화면 | 구성 |
|---|---|
| 타이틀 | 장애물 없는 조용한 골목, 가운데 고양이, 켜진 가로등, 로고, `시작하기 / 설정` 패널, 아래 조작 안내 |
| 시작 배너 | 가운데 패널에 작은 번호 + 스테이지 이름 Bold ×2 |
| 일시정지 | 어두운 막 + 패널: 제목, 구분선, 4개 항목 |
| 클리어 | 어두운 막 + 위에 "스테이지 클리어!" (`focus` 색, ×2) + 패널: 걸린 시간, 모은 꽃, 구분선, `다음 스테이지 / 다시 하기` |
| 설정 | 300×186 패널. 제목 → "조작" 안내(키캡 + 설명 3줄: 이동·점프 / 2단 점프 / 일시정지·소리·처음부터) → 소리 줄(스피커 아이콘, "소리", 오른쪽에 "켜짐/꺼짐" 글자와 스위치) → 돌아가기 → 조작 힌트. 스위치는 켜짐 민트(`flag`)·손잡이 오른쪽, 꺼짐 회색·손잡이 왼쪽. 색만으로 구분하지 않게 글자를 함께 둔다. 터치 기기에서는 키캡이 ◀ ▶ / 점프 / Ⅱ / ♪ 로 바뀐다. 항목 순서는 `src/settings-menu.js` |

## 9. 터치 조작과 화면 전환

**터치 버튼** (`index.html`, `styles.css`)
- 플레이에 필요한 것만: 왼쪽 아래 ◀ ▶ (56×56, 간격 8), 오른쪽 아래 점프 (76×76). 오른쪽 위에 작은 소리·일시정지 (40×40)
- 메뉴는 버튼 대신 **화면의 항목을 직접 눌러** 고른다 (`render.js`의 `menuHitboxes`). 그래서 ↑ ↓ 버튼은 없다
- 모양은 게임 패널과 같다: 크림 면, 진한 외곽선 2px, 모서리 깎기(`clip-path`), 아래 3px 그림자. 누르면 노란 면, 그림자가 사라지며 2px 눌림. 아이콘은 8×8 픽셀 격자 SVG(`shape-rendering: crispEdges`)
- 소리 꺼짐: 버튼 면이 푸른 회색, 스피커 옆 물결이 X로 바뀜
- **가로 화면 배치** (`main.js`의 `fit()`)
  - 옆 여백이 132px 이상 남으면 버튼을 여백에 둔다 (`body.controls-side`, 불투명)
  - 모자라면 게임을 조금 줄여 여백을 만든다. 줄인 배율이 원래의 80% 이상일 때만 (예: 844×390 → 1.44배가 1.21배)
  - 그래도 안 되면(예: 667×375) 게임 위에 반투명(55%)으로 겹치고, 소리·일시정지는 HUD 한 줄 아래로 (`body.controls-overlay`)
- **세로 화면**: 게임을 위쪽에 두고 아래 빈 곳에 "가로로 돌리면 더 크게 볼 수 있어요"
- 터치 기기에서는 안내 문구도 바꾼다: 표지판 "◀ ▶ 버튼 이동 / 점프 버튼", 타이틀 "메뉴를 눌러 선택하세요", 설정 안내 (`ui.touch`)

**화면 전환**
- 스테이지 시작(타이틀·다시 하기)과 체크포인트 부활 때, 고양이 위치에서 픽셀 원이 열린다 (0.55초 / 0.4초, 끝으로 갈수록 느려짐)
- 원 바깥은 레터박스 색 `#2f2a3a`, 가장자리는 2px 줄 단위로 끊어 픽셀아트처럼. HUD와 시작 배너는 원 위에 그린다

## 8. 목업

`mockup/`은 엔진 없이 캔버스에 직접 그린 목업이다. 게임 코드가 아니다.

| 파일 | 내용 |
|---|---|
| `lib.js` | 공용: 팔레트 `P`, 픽셀 텍스트, 패널, 스프라이트, 배경·오브젝트 그리기. **그림의 원본.** 고친 뒤 `python3 mockup/build-art-module.py`로 게임용 `src/art.js`를 다시 만든다 (`src/art.js`는 직접 고치지 않음) |
| `index.html` + `mockup.js` | 정적 화면 5개 (타이틀, 시작 배너, 플레이, 일시정지, 클리어) |
| `review.html` + `build-review.py` | **공유용 검토 페이지.** 실제 게임(`index.html`, `styles.css`, `src/`, `locales/`, 폰트)을 그대로 묶어 한 파일로 만든다. 게임을 고친 뒤 `python3 mockup/build-review.py <출력.html>`로 다시 만들어 같은 아티팩트 URL로 게시한다. 검토 도구: 흑백 보기, 배율 |
| `play.html` + `play.js` | 디자인 실험용 플레이 목업 (게임과 따로 움직이며, 더 이상 공유용이 아니다). 1-1 전체(64타일), 카메라, 패럴랙스, 체크포인트 재시작, 클리어. 검토 도구: 흑백 보기, 플레이 레이어만 보기, HUD A/B, 격자, 배율 |
| `build-artifact.py` | `play.html`을 폰트·문자열까지 넣은 단일 HTML로 묶는다 (claude.ai 공유용) |

**흑백 보기 규칙:** 흑백으로 봐도 장애물(가시, 화분)이 화면에서 가장 어두운 축에 들어야 한다. 처음 팔레트(`#ff5a4e`)는 흑백에서 풀·벽과 밝기가 비슷해 구분되지 않아 `#e8433f`로 어둡게 바꿨다.

```
python3 -m http.server 8000     # 프로젝트 루트에서 (npm run dev 와 같음)
# http://localhost:8000/mockup/index.html

```
