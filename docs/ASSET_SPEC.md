# 에셋 사양

Codex가 픽셀아트 에셋을 만들 때 따르는 기준이다. Claude Code가 관리한다.
시각 규칙의 근거는 `docs/DESIGN.md`이며, 둘이 어긋나면 `DESIGN.md`를 따른다.

지금 게임의 그림은 모두 코드로 그린 것이다(`mockup/lib.js` → `src/art.js`). 사용자가 이 그림의 분위기를 승인했으므로(2026-09-26), **새 에셋은 지금 그림을 바탕으로 더 정교하게 다듬는 것**이지 다른 스타일로 새로 그리는 것이 아니다. 크기·색·실루엣은 참고 그림과 같게 유지한다.

- 참고 그림: `assets/reference/` (현재 게임 그림을 1배 크기로 내보낸 PNG)
- 한눈에 보기: `assets/reference/_sheet_4x.png`

---

## 1. 작업 흐름

진행 상황 (2026-09-26): **P1 20개, P2 배경 3개 모두 채택·적용.** Codex 사용량 소진으로 `sign_board`와 P2는 Claude가 `scripts/build-p2.mjs`로 만들었다. 남은 것은 P3(선택)

1. Codex가 이 문서의 우선순위대로 만들어 `assets/generated/<분류>/`에 넣는다
2. 각 에셋 옆에 같은 이름의 `.json`(애니메이션 정보, 5장)을 둔다
3. HANDOFF에 만든 목록과 확인할 점을 적는다
4. Claude가 7장 기준으로 검수하고, 게임에 넣어 브라우저에서 확인한다
5. 통과한 에셋은 Claude가 `assets/sprites/<분류>/`로 옮기고 그리기 코드를 이미지로 바꾼다. 고칠 점은 HANDOFF에 적는다

분류 폴더: `player`, `tiles`, `hazards`, `objects`, `items`, `fx`, `backgrounds`, `ui`

## 2. 공통 규칙

| 항목 | 규칙 |
|---|---|
| 형식 | PNG, 투명 배경(RGBA). 1배 크기로 저장한다. 확대본을 저장하지 않는다 |
| 크기 | 표에 적힌 크기를 픽셀 단위로 정확히 지킨다 |
| 안티앨리어싱 | 금지. 알파는 0 또는 255만 쓴다. 예외: 가로등 빛 레이어(`checkpoint_lamp_glow`) 한 가지 |
| 팔레트 | `docs/DESIGN.md` 3장의 색과 `mockup/lib.js`의 `P`만 쓴다. 새 색이 필요하면 쓰기 전에 HANDOFF에 제안한다. 예외: 배경의 반투명 그늘(`P.shade`)은 아래 색과 섞은 **불투명한 색**으로 저장한다 (배경 PNG에 팔레트 밖 색 몇 가지가 생기는 것은 이 때문이다) |
| 외곽선 | 닿을 수 있는 것(플레이어, 지형, 발판, 장애물, 수집품, 체크포인트, 깃발)은 1px `#3d2b33`. 배경에는 외곽선을 쓰지 않는다 |
| 순수 검정·흰색 | 순수 검정 금지. 흰색 `#ffffff`는 구름과 반짝임에만 |
| 빨강·주황 | 위험 요소 전용 (`hazard`, `pot` 계열). 다른 곳에 쓰지 않는다 |
| 빛 방향 | 왼쪽 위에서. 밝은 면은 왼쪽 위, 그림자는 오른쪽 아래 |
| 디더링 | 쓰지 않는다 (하늘 띠 경계만 예외, 코드가 그린다) |
| 방향 | 방향이 있는 것은 **오른쪽을 보도록** 그린다. 왼쪽은 코드가 좌우 반전한다 |
| 스프라이트 시트 | 가로 한 줄. 모든 프레임 크기가 같다. 프레임 사이 여백 없음 |
| 기준점 | 발이 닿는 **아래 가운데**. 모든 프레임에서 같은 위치에 발이 오게 한다 |

## 3. 크기와 판정 기준

- 내부 해상도 480×270, 타일 16×16, 기본 지면 윗면 y=224
- 플레이어 16×16, 충돌 박스 10×14 (스프라이트 안에서 x 3~13, y 2~16)
- 실루엣은 1배 크기에서도 알아볼 수 있어야 한다 (작은 창에서는 1배 근처로 보인다)

## 5. 애니메이션 정보 (`.json`)

프레임이 2개 이상인 에셋은 같은 이름의 `.json`을 둔다.

```json
{
  "frameWidth": 16,
  "frameHeight": 16,
  "frames": 4,
  "durationsMs": [90, 90, 90, 90],
  "loop": true,
  "anchor": { "x": 8, "y": 16 },
  "hitbox": { "x": 3, "y": 2, "width": 10, "height": 14 }
}
```

- `anchor`: 게임 좌표에 맞출 점 (보통 발 아래 가운데)
- `hitbox`: 충돌 판정이 있는 에셋만. 판정 크기는 게임 코드가 기준이며, 그림이 판정보다 크게 튀어나오면 HANDOFF에 적는다

## 6. 코드 연결 (Codex 기술 작업)

- 이미지 미리 불러오기(`src/assets.js` 같은 작은 모듈): 모두 불러온 뒤 게임을 시작하고, 실패하면 지금의 코드 그림으로 그린다
- 그릴 때는 정수 좌표, `imageSmoothingEnabled = false`
- 그리기 함수를 이미지로 바꾸는 것은 Claude가 한다 (`src/render.js`, `src/art.js`). 불러오기 모듈이 준비되면 HANDOFF에 사용법을 적어 달라

## 7. 검수 기준 (Claude)

1. 크기·프레임 수·기준점이 표와 같다
2. 반투명·안티앨리어싱 픽셀이 없다 (빛 레이어 제외)
3. 팔레트 밖의 색이 없다
4. 외곽선 규칙: 닿을 수 있는 것에만 1px
5. 1배와 2배 화면에서 실루엣이 바로 읽힌다
6. 게임 화면을 흑백으로 바꿔도 장애물이 배경보다 어둡다
7. 지금 그림과 픽셀 밀도·비율이 같다 (한 에셋만 더 세밀하거나 뭉개지지 않는다)
8. 애니메이션이 과하지 않고 귀엽다 (프레임 수가 표보다 많으면 줄인다)
